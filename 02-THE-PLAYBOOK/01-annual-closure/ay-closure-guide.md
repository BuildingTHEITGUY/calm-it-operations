# 📘 Guide: Academic Year IT Operations Closure

## 🎯 Purpose
To capture all operational work that happened **outside** our main ticketing system (ITSM).
*(e.g., work done via Vendor Portals, WhatsApp, Direct Emails, Admin Consoles).*

**Why do we do this?**
1.  **Audit Evidence:** Proof that we maintained LMS, SIS, and Backups.
2.  **Justification:** We cannot ask for more budget/staff if we don't show the "hidden" work.
3.  **Closure:** To officially close the Academic Year (AY) Service Cycle.

## 📋 Instructions for Service Owners

### Step 1: Download the Template
Use the file: `ay-closure-template.xlsx` located in this folder.

### Step 2: Fill "Sheet 1-Operations-Register"
Please review your email, vendor portals, and chat logs for the past AY.
* **System:** Select the core platform (Moodle, SIS, WAF, etc.).
* **Category:** Was it a fix (Incident) or a new setting (Request)?
* **Source:** Where did the request come from? (e.g., "Vendor Support Portal").
* **Resolution Time:** Estimate how many hours you spent fixing it.

### Step 3: Review "Sheet 2-Management-Dashboard"
* Ensure your service shows `100%` (or close to it) in the SLA column.
* If you have open tickets, please close them or mark them as "Carry Forward" in the remarks.

### Step 4: Submission
* **Deadline:** [Insert Date]
* **Submit to:** IT Operations Manager

## 💡 What counts as a "Ticket"?
* Any vendor support case you opened.
* Any critical alert (Server Down, High CPU) you responded to.
* Any major configuration change (Certificate renewal, Plugin update).
* Any "quick fix" you did for a VIP user via WhatsApp.

---
**Remember:** If it isn't written down, it didn't happen. Help us protect the team's effort by recording it.
